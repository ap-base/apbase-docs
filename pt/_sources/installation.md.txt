# Installation

Install the Python core of APbase's high-performance mapping pipeline.

For production deployments, install APbase as a normal package inside the
runtime used by your API service, worker, MCP server, agent backend, or batch
container. See {doc}`production` for cloud/container sizing guidance.

## Requirements

- Python 3.12+
- `numpy`, `pyproj`, `shapely` (installed automatically as dependencies)

## Install

::::{tab-set}

:::{tab-item} Python
:sync: python

```bash
pip install apbase
```

:::

::::

:::{note}
`apbase` is not yet published to a public package index. Until then, install
from the local distribution export or the (currently private) company
repository:

```bash
pip install /path/to/apbase-python
```

```bash
pip install git+https://github.com/ap-base/apbase-python.git
```
:::

## Optional extras

:::{tip}
`GeoDataFrame`/`GeoSeries` inputs are supported by a few helper functions
(e.g. target-coordinate extraction) when `geopandas` is installed -- skip
it if you only pass plain NumPy arrays:

```bash
pip install geopandas
```
:::

## Verify the install

::::{tab-set}

:::{tab-item} Python
:sync: python

```python
import apbase

apbase.config["n_threads"] = 4
print(apbase.Map, apbase.create_map)
```

:::

::::

## Production runtime

Use a built wheel in production images whenever possible. A typical container
build compiles native Fortran/OpenMP extensions in a builder stage, repairs or
packages the wheel, and installs that wheel into a slim runtime stage.

Configure CPU parallelism at process startup:

```bash
export APBASE_N_THREADS=2
```

or in Python before handling work:

```python
import apbase

apbase.config["n_threads"] = 2
```

Keep `workers * APBASE_N_THREADS` at or below the vCPU allocated to the
service to avoid CPU oversubscription.
