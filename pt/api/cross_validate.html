apbase.cross_validate¶

Leave-one-out cross-validation for IDW, ordinary kriging, and cokriging.

This package exports the public functions used to evaluate IDW/kriging and collocated/ICM/LMC cokriging accuracy (MAE, RMSE, R2) on the same source dataset, plus select_best_model to automatically pick the statistically better method from either result.

apbase.cross_validate.cross_validate(x, y, z, *, max_points=500, seed=None, radius=None, power=2.0, max_neighbors=40, min_neighbors=3, model_values=None)

Leave-one-out cross-validate local IDW and local ordinary kriging.

Each held-out point is removed one at a time and re-estimated from the remaining source points, reusing one variogram/radius and one spatial index for both methods. Evaluation is capped at max_points held-out samples; see max_points for the sampling behavior on larger datasets.

Parâmetros:

  • x (ArrayLike) – One-dimensional source coordinates and values. Rows where any of them are NaN or infinite are ignored.

  • y (ArrayLike) – One-dimensional source coordinates and values. Rows where any of them are NaN or infinite are ignored.

  • z (ArrayLike) – One-dimensional source coordinates and values. Rows where any of them are NaN or infinite are ignored.

  • max_points (int) – Maximum number of source points evaluated by leave-one-out. If the (finite) dataset has more points than this, a random subsample of this size is drawn instead of evaluating every point.

  • seed (int | None) – Seed for the subsample draw when x has more than max_points finite points. None uses fresh entropy.

  • radius (float | None) – Local search radius shared by both methods. If None, derived as range / 3 from the fitted (or supplied) variogram, matching the default used by IDW and Kriging.

  • power (float) – IDW distance exponent.

  • max_neighbors (int) – Neighbor bounds shared by both methods. max_neighbors is capped at apbase.config["max_neighbors_ceiling"] (default 500).

  • min_neighbors (int) – Neighbor bounds shared by both methods. max_neighbors is capped at apbase.config["max_neighbors_ceiling"] (default 500).

  • model_values (ArrayLike | None) – Optional native variogram model vector (5 values). If omitted, a variogram is fit from x, y, z.

Retorna:

MAE, RMSE, and R2 for both methods, plus per-sample predictions and the held-out actual values.

Tipo de retorno:

CrossValidationResult

Levanta:

  • ValueError – If input arrays have inconsistent size, too few finite rows, invalid neighbor bounds, invalid radius, or invalid bootstrap/sample configuration.

  • NativeExecutionError – If the native cross-validation kernel reports a failure status.

Exemplos

>>> result = cross_validate(x, y, z, max_points=300)
>>> result.idw.rmse, result.kriging.rmse
apbase.cross_validate.cross_validate_cokriging(x0, y0, z0, secondaries, *, max_points=500, seed=None, radius=None, max_neighbors=40, min_neighbors=3, n_structures=2)

Leave-one-out cross-validate collocated, ICM, and LMC cokriging together.

Each of the three coregionalization models is fit once from the full dataset (same as fit()); only the primary is then held out one point at a time and re-estimated, sharing one primary spatial index and one radius across all three methods – see cross_validate() for the analogous IDW/kriging function.

Parâmetros:

  • x0 (ArrayLike) – Primary variable source coordinates and values.

  • y0 (ArrayLike) – Primary variable source coordinates and values.

  • z0 (ArrayLike) – Primary variable source coordinates and values.

  • secondaries (SecondaryInput) – Same accepted forms as fit().

  • max_points (int) – Maximum number of source points evaluated by leave-one-out; see cross_validate().

  • seed (int | None) – Seed for the subsample draw when there are more than max_points finite points. None uses fresh entropy.

  • radius (float | None) – Local search radius shared by all three methods and by every variable’s neighbor search. If None, derived as range / 3 from a variogram fit on the primary alone (independent of any one method’s own joint range fit).

  • max_neighbors (int) – Neighbor bounds shared by all three methods.

  • min_neighbors (int) – Neighbor bounds shared by all three methods.

  • n_structures (int) – Number of nested LMC structures (S), see CoKriging.

Retorna:

MAE, RMSE, and R2 per method under by_method ("collocated", "icm", "lmc"), plus per-sample predictions and the held-out actual values (identical across methods, evaluated on the same held-out samples).

Tipo de retorno:

CokrigingCrossValidationResult

Levanta:

  • ValueError – If input arrays, neighbor bounds, secondary variables, radius, or sample configuration are invalid.

  • NativeExecutionError – If a native cokriging fit or cross-validation kernel reports a failure status.

Exemplos

>>> result = cross_validate_cokriging(x0, y0, z0, {"ndvi": (xu, yu, zu)})
>>> result.by_method["icm"].rmse
apbase.cross_validate.select_best_model(result: CrossValidationResult, *, metric: Literal['rmse', 'mae'] = 'rmse', n_bootstrap: int = 2000, confidence_level: float = 0.95, seed: int | None = None) → BestModelResult
apbase.cross_validate.select_best_model(result: Mapping[str, MethodCrossValidation], *, metric: Literal['rmse', 'mae'] = 'rmse', n_bootstrap: int = 2000, confidence_level: float = 0.95, seed: int | None = None) → MultiMethodBestModelResult

Pick the statistically better method from two or more evaluated methods.

Given a CrossValidationResult (IDW vs. kriging), this keeps its original two-method behavior and return type unchanged – see below. Given any other named mapping of MethodCrossValidation (e.g. CokrigingCrossValidationResult.by_method, or a hand-built {"a": ..., "b": ..., "c": ...}), it generalizes to a best-vs-runner-up comparison across all of them and returns a MultiMethodBestModelResult instead.

Pick the better of IDW/kriging from a CrossValidationResult.

Compares IDW against ordinary kriging on the held-out samples where both methods produced a finite leave-one-out prediction (some samples can be finite for one method and NaN for the other – e.g. a singular local kriging system – so the two error series stay paired point-for-point). The lower-metric method wins (ties go to "idw", matching create_map()’s selection rule). A paired bootstrap over that common set then estimates a confidence interval for the score difference (idw minus kriging); significant is True when that interval excludes zero, i.e. the win is unlikely to be an artifact of the particular held-out sample draw.

Parâmetros:

  • result (CrossValidationResult | Mapping[str, MethodCrossValidation]) – Output of cross_validate().

  • metric (Literal['rmse', 'mae']) – Error metric used both for the point estimate and for each bootstrap replicate. "rmse" matches the metric already used by create_map() to auto-select a method. R2 is intentionally not offered here: it is monotonic in RMSE for a fixed actual-value set, but its normalization (1 - SS_res/SS_tot) depends on the evaluated subset’s variance, so it does not compare as cleanly once the two methods’ NaN patterns diverge.

  • n_bootstrap (int) – Number of paired bootstrap resamples. Memory and time scale as O(n_bootstrap * n_common_valid); the default is fast (well under a second) up to cross_validate’s default max_points=500.

  • confidence_level (float) – Two-sided confidence level for the score-difference interval, e.g. 0.95 for a 95% CI.

  • seed (int | None) – Seed for the bootstrap resample draw. None uses fresh entropy.

Retorna:

The selected method plus the paired scores, margin, and bootstrap confidence interval backing that choice. For IDW vs kriging, ci_low/ci_high bound the idw-minus-kriging score difference: a positive interval means kriging scored better, a negative interval means idw scored better.

Tipo de retorno:

BestModelResult or MultiMethodBestModelResult

Levanta:

ValueError – If the metric/bootstrap configuration is invalid, predicted/actual arrays are inconsistent, fewer than two methods are supplied, or no paired evidence exists for comparison.

Notas

This uses a percentile bootstrap on the paired per-sample errors instead of a parametric test (e.g. a paired t-test), so it needs no distributional assumption and no SciPy dependency: n_bootstrap index draws are taken once via numpy.random.Generator.integers(), and every replicate’s RMSE/MAE is computed in one vectorized reduction, not a Python loop. Resampling reuses the same draw for both methods on each replicate, which preserves the point-to-point pairing/correlation between IDW and kriging errors – essential for a meaningful difference interval.

Any held-out sample where actual itself is non-finite is also excluded (this cannot happen from cross_validate’s own output, which is filtered upfront, but protects hand-built CrossValidationResult inputs).

If one method has zero finite predictions on the common set while the other has at least one, that method wins outright (significant=True, margin=inf, no bootstrap – there is nothing to resample). If neither method has any finite prediction, or the two methods’ finite predictions never overlap on the same held-out sample, this raises ValueError: unlike create_map’s plain RMSE tie-break, this function refuses to guess when there is no shared, paired evidence to compare.

Exemplos

>>> result = cross_validate(x, y, z, max_points=300)
>>> best = select_best_model(result)
>>> best.method
'kriging'
>>> best.significant
True
