# APbase

**Intelligent, high-performance map generation for precision agriculture.**

APbase turns irregular field data (yield-monitor sweeps, soil samples,
sensor grids) into maps without asking the user to choose the mathematical
model by hand. The main entry point is `apbase.Map`: give it `x`/`y`
coordinates, values, and an output resolution; it filters the source data,
handles geographic lon/lat input when needed, builds the grid, compares IDW
against ordinary kriging, and uses the model with the lowest validation error
for that dataset.

:::{important}
APbase is a production-ready geospatial compute package. It is designed to be
imported by cloud APIs, batch workers, MCP servers, AI agents, and containerized
data pipelines that need deterministic map generation with native
Fortran/OpenMP performance.
:::

::::{tab-set}

:::{tab-item} Python
:sync: python

```python
import apbase

result = apbase.Map(resolution=10.0)(x, y, z)

result.method                  # "idw" or "kriging", picked by validation error
result.x, result.y, result.z   # compact map points inside the boundary
```

## Why APbase

- **One primary map pipeline.** `apbase.Map` is the path most users need:
  filtering, boundary/grid generation, one shared variogram fit,
  leave-one-out cross-validation, model selection, and final interpolation.
- **Automatic mathematical model selection.** The pipeline compares IDW
  against ordinary kriging and interpolates with whichever has the lower RMSE
  on the actual dataset -- no manual comparison step.
- **Performance-oriented orchestration.** The automatic pipeline reuses the
  fitted variogram for radius selection, cross-validation, and final kriging,
  avoiding redundant numerical work.
- **Production/cloud deployment fit.** APbase has a small array-in/result-out
  API, process-wide runtime controls, compact outputs, and no dependency on a
  web framework, database, desktop GIS, or notebook runtime.
- **Built for irregular, noisy point data.** The pipeline removes invalid
  rows, global outliers, and local spatial outliers before interpolation ever
  runs.
- **Sensible defaults.** Search radius for `IDW`/`Kriging` falls back to a
  fitted variogram's range when not given explicitly.

See {doc}`quickstart` for a full worked example and {doc}`production` for
deployment guidance. Use {doc}`user-guide/index` and
{doc}`methodology/index` when you need advanced control or want to audit the
mathematics behind the automatic choice.
