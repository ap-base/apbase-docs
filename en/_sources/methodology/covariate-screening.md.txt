# Covariate screening

Cokriging only helps when a secondary variable is genuinely, admissibly
correlated with the primary -- an unrelated or weakly related secondary
adds noise to the interpolation system instead of information.
`screen_secondary_variables` tests each candidate statistically before it
ever reaches {doc}`cokriging <cokriging>`, so the choice of which
secondaries to use is made from evidence rather than intuition.

## Two independent tests per candidate

For each candidate, two conditions must both hold:

**1. Significant, practically relevant correlation.** The Pearson
correlation $\rho$ between the primary and the candidate, computed over
their colocated (paired) sample, is tested against zero with a Fisher
$z$-transform {cite}`Fisher1921`:

$$
z = \operatorname{artanh}(\rho) = \frac{1}{2}\ln\frac{1+\rho}{1-\rho}
\qquad\qquad
\mathrm{SE}(z) = \frac{1}{\sqrt{n_{\text{pairs}} - 3}}
$$

giving a two-sided $p$-value for $H_0: \rho = 0$. A candidate is rejected
if this test is not significant at `alpha`, or if $|\rho|$ is below
`min_abs_rho` even when significant -- a large sample can make a tiny,
practically useless correlation statistically significant, so both a
significance and an effect-size bar are enforced.

When screening more than one candidate at once, `correction="bonferroni"`
(the default) divides `alpha` by the candidate count before testing each
one, controlling the family-wise false-positive rate across the whole
batch rather than per candidate.

**2. Admissible cross-variogram.** The primary-candidate relationship
must also be usable as a valid coregionalization component, not just
correlated at lag 0. This is checked via the Cauchy-Schwarz bound that
any valid cross-covariance must satisfy pointwise
{cite}`Journel1978,Myers1982`:

$$
\left|\gamma_{0u}(h)\right| \leq \sqrt{\gamma_{00}(h) \, \gamma_{uu}(h)}
$$

where $\gamma_{00}$/$\gamma_{uu}$ are the primary's and the candidate's
own fitted {doc}`variograms <variogram-fitting>`, and $\gamma_{0u}$ is
their fitted {class}`~apbase.cross_variogram.CrossVariogram`. The bound
is evaluated at a spread of lags out to several times the larger of the
two ranges; a candidate is rejected if more than
`max_violation_fraction` of those evaluations violate it -- a fitted
cross-variogram that is *inadmissible* would corrupt cokriging's block
system in the same way a non-PSD coregionalization matrix does (see
{doc}`cokriging`'s ICM/LMC sections), so this check catches the problem
at the input stage instead of at fit time.

## The cross-variogram itself

`CrossVariogram` generalizes the empirical semivariogram estimator to two
different variables $a$/$b$, using the parallel-bracket cross-semivariance
estimator over colocated pairs $(i, j) \in N(h)$:

$$
\hat{\gamma}_{ab}(h) = \frac{1}{2\,|N(h)|}
\sum_{(i,j) \in N(h)} \left(a_i - a_j\right)\left(b_i - b_j\right)
$$

This reduces to the ordinary semivariogram estimator when $a = b$.
Unlike an auto-variogram, `nugget`/`partial_sill` may come out negative
here -- a cross-variogram is not required to be a valid direct covariance
on its own (that is exactly what the Cauchy-Schwarz check above verifies
before anything is built on top of it).

`CrossVariogram` is symmetric and heterotopic-aware: `a` and `b` need not
share the same sample locations, since the native fit pairs them itself
via nearest-neighbor join (`max_colocation_dist` bounds how far apart a
pair may be; `None` requires an exact coincidence). This is the same
building block reused, per-pair, by ICM's and LMC's joint coregionalization
fit across every one of the $\binom{K+1}{2}$ variable pairs.

## Using the result

::::{tab-set}

:::{tab-item} Python
:sync: python

```python
result = screen_secondary_variables(x0, y0, z0, {"ndvi": (xn, yn, zn), "ec": (xe, ye, ze)})
result.selected   # {"ndvi": (xn, yn, zn)} -- only the admissible candidates
result.report     # every candidate's rho, p-value, admissible_fraction, decision, status
```

:::

::::

`result.selected` is already in the `secondaries` shape
{class}`~apbase.cokriging.CoKriging` expects, so the usual flow is
`screen_secondary_variables(...).selected` passed straight into
`CoKriging(...).fit(x0, y0, z0, secondaries=result.selected)`. A
candidate that fails for lack of data (fewer than 4 colocated pairs) or
an invalid fitted model is recorded in `report` with `decision=False` and
a reason in `status` rather than raising -- screening a batch of
candidates never aborts partway through because one of them was
unusable.
